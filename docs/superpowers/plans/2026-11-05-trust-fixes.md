# 意图、安全承接与证据关系实施计划

用户已授权自主评估、修改和测试，按 receiving-code-review 核验后执行；沿用已批准定位和发布范围，无需新增审批。采用 writing-plans / executing-plans 的逐项验证流程。项目无 Git，改动前已另存 ZIP。

目标：修复评审指出的错误承接，保留原风格与每轮历史，不把测试数据包装成临床或真实用户表现。

方案选择：采用本地高风险规则＋模型判断＋缺字段保守兜底；不增加第二次模型调用。知识/症状/日常建议/用药意图与主题分别记录；明确新话题不继承旧症状。证据使用已核对资料中的固定结论，模型只能选择结论 ID 和逐字引用，不允许自由编造支持范围。前端只能验证固定结论、正文与本轮资料相符，不能声称整段回答得到证明。

- [x] 1. tests/policy.test.mjs 与 tests/quality-cases.mjs 先覆盖胸痛、卒中、呼吸困难、出血、严重过敏等合成案例，以及否定、历史、知识、第三方、字段缺失。新增 public/policy.mjs：assessInput、resolveContext、responseRisk、nextActions。记录本测试集的急症召回、非急症误分流和意图准确率及分母；这些不是上线人群指标。
- [x] 2. public/core.mjs 和 public/app.js 在模型调用前分流、输出阶段隐藏风险承接卡片；每轮保存 context。知识新话题使用独立上下文，只有明确继续才使用上一主题。急症提示不得等待网络。
- [x] 3. public/care.mjs 维护固定证据结论，splitAnswer 解析 EVIDENCE，前端显示结论/来源/支持范围/局限/核对与复核日期。拒绝未知 ID、未出现在正文的引用、超范围资料、改写承诺疗效；旧引用标为历史模型引用。复制导出保留结构化关系。
- [x] 4. 按意图只留一个主 CTA 与一个次 CTA；知识只显示相关知识问题，症状未补全优先补充，已补全优先日常选择或反馈。摘要放会话工具。问诊提供明确退出和撤回，撤回提交后不再把旧选项带入上下文。原生 radio＋下一步，不因方向键更换选择而自动跳题；键盘焦点正确返回。
- [x] 5. 本机隐私入口解释保存内容、保留期限、模型传输与导出；清除全部仅删除本产品键，清除世代阻止旧标签页和生成中回写。偏好 30 天有效、仅用于症状/日常建议，支持本轮不使用和清除；旧偏好需重新确认。不增加无同意的远程行为采集。
- [x] 6. npm test、Python 配置测试、语法和 public 凭据扫描；独立代码审查；Chrome 本地验证错误元数据、知识切换、完整历史、键盘单选、跳过退出、撤回、清除与跨标签页、移动布局。仅在测试数据环境执行删除测试。
- [x] 7. 沿用原 POPO 发布权限，线上真实模型验证新话题、证据结构及风险分流，保存截图；记录已做、测试限制与下一步场景建议。

场景范围：让原有疲惫/消化入口更明确；传统导引知识使用独立主题。睡眠和八段锦资料仍不等于疲惫/消化、用药或女性周期的证据。新增来源按权威原文、适用范围、限制、核对日期与定期复核管理，再扩展日常消化场景。图像、实时搜索、周期预测本轮不加入。
